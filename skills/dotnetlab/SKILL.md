# Tedd.DotNetLab — Scientific .NET Performance Engineering

Drive C# and .NET performance work as a disciplined experimental loop: **measure first, localize the bottleneck, formulate one falsifiable hypothesis, freeze the statistical plan before timing, verify semantics and emitted machine code, and retain only repeatable measured wins.**

Do not guess bottlenecks from syntax, claim speedups without controlled before/after evidence, or load every reference file at once. Read **only** the operational reference and C# optimization playbook matching your current step and measured bottleneck.

## The 7-Step Scientific Method Loop

| Step | Action | Exit Gate & Evidence |
| --- | --- | --- |
| **1. Discover & Scope** | Query `lab.discover` (`workspace`, `profiles`, `targets`, `capabilities`, `compatibility`, `scenarios`). Define cold vs steady-state objective, workload unit, primary metric, and mandatory guardrails. | Bound `target_id`, PID/start, `expected_target_epoch`, runtime version, scenario/version/input hash, and observer mode. |
| **2. Baseline & Profile** | Reproduce workload with an independent correctness oracle. Capture EventPipe stacks/counters (`cpu-diagnostic`, `allocation-diagnostic`, `jit-and-contention-diagnostic`, `baseline-context`, `runtime-metrics-context`) -> `analyze_stacks` & `analyze_capture` -> check inlining failures (`FailReason`), lock contentions, and GC. | Baseline epoch + hotspot breakdown (`self` vs `inclusive`), inlining blockers, contention duration, allocation bytes/op vs GC pause/retention. |
| **3. Formulate Hypothesis** | Route the measured bottleneck to **one** playbook below. Rank 1–3 high-leverage candidates along the priority ladder: *eliminate work/algorithm -> memory & layout -> JIT visibility & bounds -> dependencies & branches -> SIMD & intrinsics -> concurrency*. Record `create_hypothesis`. | `hypothesis_id` (`proposed`) with explicit mechanism, directional prediction, falsifier, semantic invariants, and **one causal change** (unless using a $2\times 2$ `FactorialDesign`). |
| **4. Freeze Plan** | Call `create_plan` (or `create_individual_latency_plan` / `create_quantile_plan`) **before** collecting candidate data. Freeze `variants`, `blocks`, `operations_per_run`, `warmup_batches`, `seed`, `primary_metric`, policies, guardrails, and `family_size`. | Retained `plan_id` (`planned`) with prospective thresholds and error-spending family size frozen prior to execution. |
| **5. Implement & Verify Codegen** | Apply the minimal C# delta. Validate edge cases (empty, singleton, partial vector tails, overflow, NaN/signed-zero, aliasing, lifetimes) via an independent oracle in `Validate()`. For JIT/bounds/branch/SIMD hypotheses, inspect Tier 1 x64 assembly via `capture_jit_disasm` (generics, spans, structs, SIMD, inlined callers) or `lab.inspect` (`native` / `native_diff`). | Passing semantic checks + verified codegen. If the JIT already eliminated the cost (e.g., bounds check already hoisted), revise the hypothesis before running timed blocks. |
| **6. Execute & Compare** | Obtain required human CLI grants (`grant`, `grant-scratch`), start `lab.run` (`start`) once with an `idempotency_key`, poll `status` to quiescence, verify completed work/validation, and run `lab.compare`. | Completed `execution_id` and `comparison_id` (`testing` -> `supported` / `not_supported` / `inconclusive`). Never cherry-pick runs or expand sample budgets post-hoc. |
| **7. Confirm or Revert** | If `not_supported` or `inconclusive`: **revert code changes**, keep catalog evidence via `revise_hypothesis`, and iterate. If `supported`: confirm source promotions via fresh normal builds (`start_confirmation` -> `lab.compare` `normal_build_confirmation=true` -> `record_decision`), then **re-profile** because bottlenecks shift. | Clean working tree with only verified wins integrated, durable invariants documented, and notebook dispositions up to date. |

## Analytical & Experimental Guardrails

- **Quantitative Models:**
  - *Amdahl's Law:* $\text{Speedup} \le 1 / ((1 - f) + f / s)$ where $f$ is the measured **non-overlapping** critical-path fraction. Never sum overlapping `inclusive` stack shares to estimate $f$.
  - *Roofline:* Attainable rate $\le \min(\text{Peak Compute}, \text{Sustainable Bandwidth} \times \text{Operational Intensity})$. Wider SIMD vectors do not reduce bytes transferred from DRAM.
  - *Dependency Recurrence:* Idealized loop-carried cost $\ge \max(R, L / K)$ cycles per element ($L$ = latency, $R$ = reciprocal throughput, $K$ = independent chains; need $K \ge \lceil L / R \rceil$ chains to saturate execution ports).
- **Observer Limits:** EventPipe stack samples locate on-CPU activity—they do **not** measure exact call counts, per-call latency, off-CPU lock/I/O waits, or hardware PMU events (IPC, branch misses, LLC/TLB misses, port pressure). Require external PMU tools (`perf`, VTune, uProf) before claiming hardware-counter causality. Controller resource usage is not target cost; `quiet-validation` omits EventPipe providers but does not unload an already-attached CLR profiler or reset Tiered PGO history.
- **Workload Contrasts:** Test mechanism-relevant boundaries rather than a blind Cartesian product: empty/singleton, below-vector, exact-vector, partial vector tail, L1-resident vs beyond-LLC, predictable vs random-50% predicates, hit vs miss skew, and accelerated ISA vs scalar fallback.

## Non-Negotiable Contracts

1. **MCP Wire Format:** Six base tools (`lab.discover`, `lab.inspect`, `lab.experiment`, `lab.run`, `lab.query`, `lab.compare`); optional `lab.patch` requires `--enable-native-extension`. Payloads wrap in `{"request":{...}}` using `action` (or `view` for `lab.query`) discriminators and decimal strings for 64-bit epochs, revisions, byte counts, and seeds. Check both the MCP `isError` flag and envelope `status` (`code`, `message`, `recovery`).
2. **Human-Only Grants & Admission Control:** Discovery grants zero execution or inspection authority. Only the human issues CLI grants (`grant`, `grant-scratch`, `grant-build`, `grant-confirmation`, `grant-profiler-attach`, `grant-cil`). When connected to a shared controller (`connect`), human CLI commands forward automatically over the local pipe to the live service without disconnecting; for dedicated `serve` controllers, stop or idle the controller first. Revalidate `target_id` and `expected_target_epoch` after grants. Never attempt to mint grants, bypass admission, or stop another user's controller.
3. **Host Serialization & Side-Effect Safety:** A machine-wide mutex serializes timed runs and captures across cooperating controllers, but unrelated host processes can still perturb timings. Inspect target startup, `Setup`/`Reset`/`Cleanup`, callbacks, and configuration before running scenarios; **block execution against any unverified database or production write target** unless explicitly authorized by the user.
4. **Workspace & Scratch Hygiene:** Keep SQLite catalogs, traces, staged builds, and temporary scripts inside the configured `Tedd.DotNetLab` workspace or the user's designated scratch root (never scatter temporary files in repository roots, home directories, or system temp). Clean up only owned disposable scratch artifacts after verified shutdown; preserve catalog evidence.
5. **Statistical & Operational Integrity:** Inner loop iterations and sequential blocks inside one process are not independent process sessions. Batch means do not establish `p99` tail latency. Retain accepted `operation_id` and `idempotency_key`; on timeout or disconnect, query operation/mutation history before retrying, and never run quiet benchmarks on a ReJIT-tainted process.
