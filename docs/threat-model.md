# Local trust boundaries

The protected assets are target identity and execution state, scoped grants, mutation/restoration evidence, immutable plans and artifacts, and the privacy of diagnostic data. The trusted principals are the local developer and application owner. The controller, harness, parser worker, and profiler execute under that developer's account. The operating system, pinned runtime, approved binaries, and the workspace's access controls are prerequisites for these boundaries.

Trace strings, imported bundle members, scenario results, model-generated requests, and native control frames are data. They cannot issue a grant, add an arbitrary executor, redefine an existing plan, or turn incomplete evidence into a successful result. The model-facing interface is local stdio with six base tools and an explicitly enabled seventh patch tool. The human CLI issues scoped grants independently.

| Boundary / threat | Enforcement | Residual scope |
| --- | --- | --- |
| MCP request to action: arbitrary command, extra field, or oversized request | Typed discriminated requests, strict JSON members, schemas, bounded arguments, resource limits; no shell executor | The client and local developer must protect their own credentials and tool configuration. |
| Controller to target: pipe substitution or PID reuse | Current-user Windows pipes, kernel-reported peer PID, process/start identity, runtime handshake, expected epoch | Endpoint discovery alone is not a capability certificate. Identity must remain valid at action admission. |
| Grant to action: confused scope, expiry, replay, or exhaustion | Workspace/target/start identity, permission class, candidate/method content scope, expiry, operation count, idempotency and revision checks | Another process with workspace-write access can change locally stored authority. Grants are not a boundary against a compromised operating-system account. |
| Imported or stored evidence to parser: corrupt input or excessive expansion | Artifact length/hash checks; bounded worker protocol, output, duration and memory; worker process containment; incomplete/corrupt states | A worker process and resource job are not an operating-system security sandbox. Keep parser dependencies qualified. |
| Artifact path to filesystem: traversal, link substitution, or deletion outside owned paths | Canonical roots, relative-path validation, reparse-point rejection, same-filesystem sealing, scoped deletion, reference/pin checks | Restrict workspace access; hashing detects corruption, not an adversary capable of replacing both content and metadata. |
| Runtime method to snapshot: stale body, wrong module, or unsafe address reuse | MVID/token/module image/signature identity, bounded runtime-provided regions and mappings, observation epochs, qualified acquisition sequence, copied bytes | Unsupported bodies fail explicitly. Inspection perturbs the target and is excluded from timed intervals. |
| Candidate to running process: invalid CIL, active work, uncertain application, or partial revert | Qualified CIL subset, exact body hashes and epochs, preflight, target-exclusive lease, harness quiescence, per-method ReJIT/inliner evidence, scenario oracle, durable journal | Active native frames may finish their old code. Restoration is a verified transition, not proof that every arbitrary application state was reversed. |
| Native experiment to source promotion: provisional result treated as adoption | Native outcomes remain non-promotable; immutable source/build/scenario identities and fresh normal-build confirmation govern promotion | An application build may perform external writes during startup. The application owner must authorize those effects separately. |
| Workspace to export: unwanted disclosure | Explicit inclusion list, export grants, immutable manifests/hashes, privacy-filtered omission and bounded import | An included raw trace may contain sensitive content. Filtering does not provide arbitrary trace redaction. |
| Distribution to execution: substitution or undocumented dependencies | Independently trusted archive hash, exact file inventory/hashes, runtime pins, locked NuGet content integrity, dependency notices, explicit signing observations | Unsigned binaries lack publisher authentication. License inventory does not certify vulnerability status or the supported live-runtime scope. |

Failure evidence must remain truthful. A timeout is not an acknowledgment that a target stopped, a cancellation request is not confirmed quiescence, missing counters are not zero, and a nonsignificant comparison is not equivalence. Uncertain or partial restoration leaves the target tainted and blocks further mutation until the documented recovery conditions are satisfied.

Review changes at the boundary they affect. Runtime upgrades require new native/API fixtures; provider/parser changes require trace and loss fixtures; statistical changes require independent oracles and simulations; grant, identity, filesystem, or restoration changes require explicit negative tests. The [security reporting policy](../SECURITY.md) defines the information needed for a private reproduction.
