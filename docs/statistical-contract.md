# Statistical contract

## Harness individual-operation timing

`lab.experiment` action `create_individual_latency_plan` freezes the registered scenario version, input hash, variant, operation count, warm-up count, and duration. `lab.run` action `individual_latencies` requires the target epoch and an execution grant. The harness invokes `ExecuteBatch(1)` once per measured operation, or awaits each `ExecuteBatchAsync(1)` completion. Every invocation must report exactly one completed operation. Validation, cleanup, and quiescence remain required.

The ordered vector contains exact monotonic tick durations and their frequency. Synchronous and asynchronous observers are identified separately as `harness_sync_individual_stopwatch/v1` and `harness_async_individual_stopwatch/v1`. Each interval includes workload waiting and timer-observer costs; no assumed overhead is subtracted. Calling one-operation batches changes the invocation pattern relative to ordinary batch measurement and must be part of the declared workload/observer identity. The outer elapsed interval also includes loop and vector-recording costs. Vector storage is allocated before the measured allocation envelope. Asynchronous execution provides process allocation deltas, without a current-thread allocation claim.

Each run retains at most 10,000 individual operations in a sealed, pinned measurement artifact. Its catalog index omits the vector; `lab.query` view `individual_latency_slice` returns at most 1,000 ordered tick durations per request. Ordinary batch measurement uses its original single-batch path and has no individual vector. A collected vector alone does not establish independent sessions or a preregistered paired quantile dataset.

Native original-body-ReJIT and candidate-ReJIT timing requires `compilation_control_id` in the batch or individual plan. The selected completed A/A protocol must match the target session, method/callers, runtime/observer, flags, scenario/input, operation count, and warm-up. Its result and artifacts are verified before admission. Every native run records compilation evidence checked around timing. Reversion retains `restored_original_version`; it does not recover a pristine normal-compilation label. The control is descriptive single-session evidence and does not certify independent samples, equivalence, or promotion. Fresh normal-build plans reject this session-bound binding.

## Retained individual-observation quantiles

`lab.experiment` action `create_quantile_plan` freezes observation type (`frame_time` or `individual_operation_latency`), workload and observer identities, ordered cluster/block layout, per-arm observation budget, quantile, seed, resample count, family alpha/size, independence declaration, absolute useful/regression thresholds, and duration. The plan hash includes its identity and freeze time. Units are nanoseconds. Batch averages and sampled-stack observations cannot be substituted for individual latencies.

An imported complete JSON artifact has `plan_id`, `plan_hash`, `observation_type`, `unit`, `workload_identity`, `observer_identity`, and `blocks`. Each block retains ordered `baseline` and `candidate` arrays with exactly the frozen observation count. `register_quantile_observations` validates the entire budget and schema, verifies the artifact hash, requires registration after plan freeze, and pins the source. This interface labels inputs `supplied_individual_observations_not_capture_certified`; a valid schema does not independently establish collection fidelity or session independence.

For registered harness collection, `create_quantile_plan` takes `harness_plans` with `baseline_plan_id` and `candidate_plan_id`. Both individual-latency arm plans must agree on scenario/version/input, warm-up, and the frozen per-arm observation count. The quantile plan retains their exact revisions/hashes and a randomized baseline/candidate order for each block, generated from the plan seed with SplitMix64, rejection sampling, and Fisher–Yates. The returned order governs execution as well as later verification.

`register_quantile_harness_runs` accepts every declared block ID and its baseline/candidate run IDs. Every source must be a completed, correct, quiescent individual run accepted after the quantile plan was frozen. The source vector and bounded run index must agree, individual durations must fit their outer clock envelope, and paired arms must follow the frozen nonoverlapping order in the same process epoch. All blocks within a cluster use one process session; different clusters require distinct PID/start identities. Build, runtime configuration, clock frequency, and observer footprint must agree across the dataset. Native-profiler compilation regimes require separate qualification and cannot enter this bridge.

The bridge seals nanosecond arrays derived from ordered exact ticks and a separate manifest binding each run revision/hash and source artifact hash. Both manifests and source measurements are pinned. Every comparison re-verifies the original vectors and reconstructs the arrays before inference, including after controller restart. Supplied arrays cannot acquire this provenance through a caller-provided label. Results identify `verified_registered_harness_individual_observations/v1`; distinct process sessions still require the frozen independence declaration and do not prove independence, workload representativeness, or statistical coverage. Frame-time input uses the supplied-observation interface.

`lab.run` action `compare_quantiles` takes the dataset ID and idempotency key. The estimator pools retained individual observations within each arm and computes the declared linear quantile using `h=(N-1)*p`. Blocks within each declared session/super-block are concatenated in frozen order. The bootstrap samples complete paired clusters with replacement, applies the same sampled cluster indices to both arms, preserves their internal observations, and recomputes candidate-minus-baseline quantiles. Clusters are sampled uniformly; the pooled observation statistic retains each selected cluster's declared observation count. Unequal cluster sizes do not justify resampling individual rows independently.

The default is 10,000 SplitMix64/rejection resamples and a percentile interval at local alpha `alpha_family/family_size`. Work and data are bounded to 100,000 observations and 50 million observation-resample operations. Plan admission requires at least five expected bootstrap draws in each requested tail. Cancellation is checked during resampling. Fewer than ten declared independent clusters, or unresolved cross-cluster dependence, produces descriptive output with `insufficient_independent_evidence`; many adjacent rows do not increase independent evidence. A degenerate bootstrap distribution remains descriptive.

Strictly crossing a frozen absolute threshold permits a separately labeled approximate bootstrap threshold assessment. The result returns no difference p-value, TOST p-value, equivalence claim, or source-promotion eligibility. It retains the quantile convention, estimator, interval coverage, seed/algorithm, raw observation count, declared/independent cluster counts, plan hash, source hash, and provenance limitation. Results and sealed manifests survive restart; a new comparison re-verifies source bytes. Replaying an idempotency key returns its original operation.

`tests/Fixtures/statistics/quantile_reference.py` independently generates an unequal-session-cluster fixture with NumPy's linear quantiles and the declared random algorithm. Its checked-in 10,000-resample reference is tested against the public workflow with `1e-9` ns absolute tolerance. This reference establishes implementation agreement for that fixture; statistical coverage calibration and workload representativeness require their own evidence.

This specification is for reviewers of experiment plans and engine evidence. The paired ratio algorithm is `paired-log-ratio/v2`; the objective-vector policy is `paired-objective-vector/v1`. The independent reference implementation is [reference.py](../tests/Fixtures/statistics/reference.py), with versioned inputs and outputs in [golden.json](../tests/Fixtures/statistics/golden.json).

## Observation and inference units

Every paired row represents one declared matched block. A batch-normalized elapsed observation is elapsed nanoseconds divided by actual completed operations. It is a batch mean; its quantile is not a quantile of individual operation or frame latency. A throughput observation is actual completed operations divided by elapsed seconds. Process allocation deltas cover the process, including concurrent allocations during the envelope. Thread allocation deltas apply only to an eligible unchanged thread. Allocation samples are a separate evidence type.

The plan declares block independence and its justification. The minimum of ten independent blocks is a product guardrail, not a power guarantee or a proof of independence. Duplicate cluster IDs cannot increase the independent-unit count. Missingness, unit, observation type, scope, correctness, observer footprint, runtime, and completed work are checked before inference. A timing observer mismatch blocks timing inference. Scoped allocation deltas can remain descriptive with an observer warning; they do not establish a code-only allocation effect.

## Native session-level inference

For native body trials, a frozen process-session series compares original-body-ReJIT with candidate-ReJIT as expected treatment differences. The estimator is `paired-session-mean-log-native-batch-cost/v1`: average matched log costs within each session, then apply the paired log t/TOST procedure with equal session weights. Runtime/load, flags, code, caller, correctness, and restoration evidence remain verified; live epochs and ReJIT IDs are session-scoped. Each process session is one analysis unit. The frozen plan must declare independence and adequate reset/carryover handling for inference; neither distinct PIDs nor randomized order independently proves those assumptions. Native results remain exploratory for source-promotion purposes. The [native qualification guide](native-qualification.md#native-process-session-series) defines plan admission, durable registration/comparison, and retained-source verification.

## Retained execution windows

`lab.query` with `view=run_window`, an analysis ID, and a run ID resolves a half-open execution interval from target-side monotonic start/end ticks. The measurement artifact, capture process/start/runtime identity, raw trace, and derived analysis are verified. Controller arrival time is never substituted for a workload boundary. `measurement_start` and `measurement_end` payloads carry the actual timer ticks, although their events are published after timing. Only `clock_before`/`clock_after` records contribute target-tick/trace-event-time calibration pairs.

The centered affine fit reports its slope and maximum residual. Residual tolerance is explicit, finite, and at most 10 ms; the default is 1 ms. The qualified slope differs from the target tick frequency by at most 5000 ppm. Execution must lie within retained calibration and observed trace coverage; unsupported extrapolation provides no precise overlap. A fit residual is an observed consistency indicator, not a guarantee against unobserved marker scheduling delay. A residual at the execution-resolution scale makes the result partial.

Rejected affine fits retain `clock_fit_failure`: pair count, failure stage, tolerance, and any finite candidate slope/residual with the worst observed pair. Nonfinite candidates remain null. Failure stages distinguish insufficient/invalid pairs, missing tick separation, nonfinite fit, nonpositive slope, and excessive residual. These observations explain rejection without supplying an accepted mapping, mapped interval, or overlap value. Diagnostic records have a distinct derived identity and remain sealed across restart; historical windows keep their original hashes. Accepted windows omit this optional field.

If semantic markers are missing but sealed measurement ticks and a valid covering clock fit exist, the result records `persisted_measurement_clock_recovery` and a warning. Without such mapping, no scenario window is invented. Reprocessing produces a versioned result; historical parser/analysis provenance remains unchanged.

GC cycles and runtime suspensions are reconstructed separately in event-time order. Runtime instance plus GC number identifies a cycle. Incomplete suspension endpoints remain nullable with an explicit completeness reason. GC overlap unions `SuspendForGC` and `SuspendForGCPrep` suspension-start/restart-end intervals clipped to execution; debugger and other suspension reasons remain available through `view=suspensions` and do not enter the GC-specific value. This reason distinction follows the [PerfView runtime event analysis](https://github.com/microsoft/perfview/blob/main/src/TraceEvent/Computers/TraceManagedProcess.cs). A background GC cycle duration is not a pause duration. Overlap is process-level correlation and does not attribute causation to a selected method.

Missing endpoints, loss/unknown loss, incomplete capture, parser limitations, and insufficient clock resolution produce partial or unavailable evidence. No complete retained GC suspension means provider coverage is unestablished, so silence is not reported as zero. Complete observed suspensions outside a covered window can produce a real zero overlap. Concurrent windows may share a pause; their totals must not be summed as unique process pause time. Expired raw trace returns `artifact_expired` for a new raw-dependent query even if historical summaries remain retained.

Plans with a GC primary objective or guardrail freeze `diagnostic_windows`: residual tolerance (default 1 ms), parser version, and window algorithm. Completed captured executions bind the original `analysis_id`. Subsequent reprocessing, a later capture, or another target cannot replace that binding. An execution without its original analysis returns missing diagnostic evidence.

Ordinary objective and factorial comparisons derive `gc.suspension_overlap_ns` from those verified execution windows. Raw trace and analysis hashes, process/runtime/epoch/profile identity, sealed measurement boundaries, and the frozen algorithms are checked. A sealed `execution-gc-objectives/v1` manifest retains source record revisions/hashes, measurement artifact hashes, full window results, warnings, partial observed values, and dependence blockers. The bounded objective index links to this manifest. Raw trace and analysis inputs are pinned when verified; derivation reads the source summary once and enforces the plan's duration and artifact-size limits.

Only available window metrics enter inference. Trace loss, incomplete suspensions, insufficient clock evidence, corruption, and expired inputs preserve their availability/reason and block the GC objective. Independently valid elapsed/throughput/allocation evidence remains evaluable. A complete GC suspension intersecting runs in several declared blocks adds `gc_episode_spans_multiple_declared_blocks`; repeated exposure to one episode cannot manufacture independent GC evidence. Conditional factorial effects and the interaction use the same bound diagnostic manifest.

Historical sealed vectors remain readable after raw-trace loss. A new comparison re-verifies its sources and records expired diagnostic evidence with a distinct manifest/vector identity. Quiet fresh-process confirmation without diagnostic collection retains an unavailable mandatory GC guardrail and cannot promote on that evidence. GC overlap remains process-level correlation with a workload interval, without method attribution.

## Primary objective policies

`create_plan` and the experiment inside `create_confirmation_plan` select `primary_metric`. Elapsed-cost plans can derive their default primary thresholds from the analysis policy. Throughput, allocation, and GC-overlap objectives require `primary_policy`, with the same metric name, qualified unit/observation kind/direction/scale, and predeclared equivalence, useful-benefit, regression, and minimum-block thresholds. A primary policy cannot be descriptive-only. The plan hash binds the complete policy; neither comparison nor source-review decisions can substitute another objective afterward.

`scenario.throughput_ops_s` (also accepted as `scenario.operations_per_second`) measures completed operations per measured batch second, with higher values preferred. Its paired estimator is the geometric mean of matched batch-rate ratios. Ratio equivalence bounds straddle one; useful-benefit thresholds exceed one and harm thresholds lie below one. Throughput aliases cannot be counted as separate primary/guardrail objectives.

`allocation.process_bytes` and `allocation.thread_bytes` are total allocation-counter deltas in bytes. Their normalized counterparts are `scenario.process_allocation_bytes_per_operation` and `scenario.thread_allocation_bytes_per_operation`. Allocation policies use absolute differences, with equivalence bounds straddling zero and negative useful-benefit thresholds. Process scope includes concurrent allocations; current-thread scope requires eligible same-thread execution. An async primary thread-allocation request provides `not_applicable` evidence and blocks inference/promotion. Zero baselines remain valid absolute inputs; degenerate differences remain descriptive.

Explicit-policy comparisons expose `primary_effect` with units, direction, estimator, availability, uncertainty, and the frozen policy. Absolute effects leave the legacy ratio, percent-change, and ratio-interval fields null. Ratio effects retain actual candidate/baseline ratios, including ratios above one for beneficial throughput. The bounded comparison index retains `input_run_count` and an `objective_vector_id`; the pinned vector artifact retains the complete input run IDs. Fresh normal-build confirmation applies the same primary policy and every mandatory guardrail before source-review eligibility. Default elapsed comparisons preserve their existing wire shape.

## Positive-cost ratio procedure

For positive matched costs `b[j]` and `c[j]`, define `d[j] = log(c[j]) - log(b[j])`. This avoids an overflowing intermediate `c/b`. For `n` independent blocks:

```text
m = arithmetic_mean(d)
SE = sample_standard_deviation(d) / sqrt(n)
df = n - 1
effect = exp(m)
ordinary interval = exp(m ± t(1-alpha_local/2, df) * SE)
equivalence interval = exp(m ± t(1-alpha_local, df) * SE)
```

The effect is a geometric mean of matched ratios. It is not the ratio of arithmetic mean costs. Standard error is on the log-ratio scale; reported effect and interval endpoints are ratios. A ratio below one benefits a lower-is-better metric. A ratio above one benefits a higher-is-better metric. The direction is explicit in each metric policy.

The two-sided difference test uses `2 * survival_t(abs(m/SE), df)`. For equivalence bounds `L < 1 < U`, TOST uses the maximum of `survival_t((m-log(L))/SE, df)` and `cdf_t((m-log(U))/SE, df)`. Equivalence passes only when both tests are strictly below local alpha and the equivalence interval is strictly inside the declared bounds.

## Absolute differences

Allocation observations may be zero. They use `d[j] = c[j] - b[j]`, an arithmetic mean difference, and an absolute margin in the declared unit. No epsilon or percentage division by zero is used. The standard error and degrees of freedom use the same paired t model. Interval endpoints remain `m ± critical * SE` without exponentiation. TOST uses the absolute equivalence bounds directly. Difference tests concern zero absolute change.

Zero variance produces a descriptive estimate with `degenerate_variance`; it provides no confidence interval or equivalence guarantee. Intervals whose endpoints collapse under binary64 rounding produce `measurement_resolution_floor`. Nonfinite effects, invalid log inputs, overflowing contrasts/intervals, and an unrepresentable local alpha cannot become usable inference.

## Frozen decision policy

For lower-is-better metrics, useful improvement requires the upper ordinary bound strictly below the useful-improvement threshold. Meaningful regression requires the lower ordinary bound strictly above the regression threshold. Higher-is-better metrics reverse these inequalities. Practical equivalence requires the separate TOST criterion. Other usable data is inconclusive. Policy bounds are disjoint around one for ratios and zero for absolute differences.

A mandatory lower-is-better guardrail passes noninferiority only when its upper ordinary bound is strictly below the declared harm margin. For a higher-is-better guardrail, its lower bound must be strictly above that margin. A confidence endpoint exactly on the margin does not pass. Unknown, invalid, degenerate, descriptive, or unresolved mandatory guardrail evidence blocks promotion. A guardrail explicitly declared descriptive before sampling is reported without inference and does not gate promotion.

The fixed family allocates `alpha_local = alpha_family / family_size`. Its size covers every planned inferential candidate-arm/metric comparison, including the primary metric; missing evidence cannot shrink that family after observation. Descriptive guardrails do not consume tests. All effects used for an automatic decision share the same family allocation. Ordinary coverage is `1-alpha_local`; equivalence coverage is `1-2*alpha_local`.

Promotion requires a useful primary benefit, every mandatory guardrail, and separate preregistered normal-build fresh-process confirmation. The decision is evidence for source review and does not modify, commit, deploy, or publish source. A frozen confirmation execution cannot absorb extra samples or changed margins. Exploratory narrative revisions do not replace the selected evidence revisions/hashes.

## Multiple objectives and Pareto relations

The engine returns the complete effect vector rather than a summed percentage or undeclared weighted score. Different units retain their own absolute or relative scales. Candidate Pareto dominance requires every compatible ordinary interval to establish no worsening relative to zero change, and at least one to establish strict benefit, using the declared directions and a consistent family. Overlapping uncertainty, missing evidence, and descriptive objectives leave dominance unresolved. Passing a noninferiority margin is weaker than proving Pareto dominance.

## Four-arm factorial designs

A factorial plan freezes ordered variants `00`, `10`, `01`, and `11`, two registered component candidates, their registered combination, and an interaction scale for every metric. The combination must contain exactly those components. The scenario produces randomized complete four-arm blocks; an incomplete arm cannot be invented, silently excluded, or replaced with historical baseline samples. Ordinary four-variant plans without this declared mapping cannot request interaction inference.

`lab.compare` with `include_factorial=true` returns a bounded index linked to complete sealed evidence. It retains five objective vectors: A alone (`10/00`), B alone (`01/00`), joint (`11/00`), A given B (`11/01`), and B given A (`11/10`). These comparisons use the metric's frozen ratio or absolute-difference policy. A standalone regression remains in history even when the joint or conditional effect is beneficial.

For each complete block, an absolute interaction is `x11 - x10 - x01 + x00`. A log interaction applies the same contrast to the four log costs and is reported in `log_ratio_contrast` units. Allocation interaction uses an absolute scale, so zeros remain valid. The mean contrast, paired-block standard error, `n-1` degrees of freedom, and t-based ordinary interval are computed over complete independent declared blocks. The two-sided difference p-value tests zero interaction. No interaction TOST or automatic equivalence claim is borrowed from the standalone ratios.

The family covers five pair contrasts plus one interaction per inferential metric: at least `6 * inferential_metric_count` comparisons. An explicitly descriptive metric retains descriptive pair/interaction output without consuming tests. Nonfinite data, duplicate/dependent blocks, insufficient independence, zero variance, and rounded interval collapse retain their invalid, blocked, or descriptive states. The oracle includes absolute interaction `-11` and the distinct log contrast from the same noisy four-arm dataset. Percentage improvements are never added to manufacture a joint result. Factorial results remain exploratory for source promotion; a selected joint candidate requires separate normal-build confirmation.

## Evidence and interpretation

Full vectors, including input run IDs, are sealed and pinned as immutable artifacts. Bounded catalog indexes retain effects without repeating the input ID lists and identify the complete detail artifact. Historical records and decisions are not overwritten by another algorithm version. Ordinary scenario comparison remains exploratory for source promotion.

`lab.experiment.create_baseline` selects distinct completed, correct, quiescent run or joined normal-build session IDs and a declared role. Its sealed manifest binds exact source revisions/hashes and measurement artifacts. Scenario/input, control variant, work count, reset/warm-up, profile/observer, retained DLL hashes, runtime-configuration hash, runtime/platform, and code epoch must agree. Epoch-bound profiler selections also retain their process scope. The manifest and every selected measurement are pinned. CPU model, affinity, power policy, observed tier, PGO history, and background load remain explicitly unknown in this footprint.

`set_baseline_alias` assigns an ASCII name of 1–64 letters, digits, dots, underscores, or hyphens to a selection. Names are case-insensitive; updates require the expected catalog revision. The alias has history, while the selection is immutable. A plan accepts one `baseline_id` or `baseline_alias_id` and stores the exact selection revision/hash and, where used, alias revision/hash. A later alias update cannot redirect an existing plan.

Execution verifies the frozen evidence and live build/settings identity before measurement. Runtime and observer identity are also checked around each cooperative run. Normal-build confirmation verifies its selected control against the fresh owned process. These selections are historical anchors: the explicit sampling policy is `fresh_matched_control_runs`, and historical samples are not silently reused as new matched arms. Missing/corrupt evidence or identity mismatch blocks execution; correcting the selection requires a new record and plan.

Use these interpretation templates with the actual policy, interval, units, and design:

- Improved: “The declared candidate/baseline estimand meets the preregistered useful-benefit threshold under this matched-block design.”
- Equivalent: “The declared estimand is equivalent within the stated bounds under this design.” This does not mean identical distributions or implementations.
- Inconclusive: “The interval includes effects that do not resolve the declared improvement, regression, or equivalence criterion.” Retain the unresolved range.
- Guardrail blocked: “The primary benefit does not establish promotion eligibility because the named mandatory guardrail is regressed, unknown, or unresolved.”
- Descriptive: “The observed effect is descriptive; this evidence does not provide the requested inferential guarantee.”

The SciPy oracle imports no production calculations. Unit tolerances are absolute `1e-11` for effect/standard-error values, `1e-10` for interval endpoints, and `1e-8` for log p-values on the retained fixtures. Assumptions and workload representativeness remain distinct from numerical agreement with the oracle.

## Seeded statistical qualification

[simulation-plan.json](../tests/Fixtures/statistics/simulation-plan.json) freezes sixteen designs, each with 10,000 experiments and a separate seed. The sampler is SplitMix64 with strictly open 52-bit uniforms and Box–Muller normal draws, discarding the second variate. Designs cover normal null/useful effects, both equivalence boundaries, effects inside/outside those boundaries, unequal-variance Welch, additive differences, heavy tails, symmetric outliers, AR(1) dependence, independent session-level aggregates, a fixed five-test family, adaptive winner selection followed by a fresh data partition, and paired cluster-median bootstrap with correlated frames.

Positive-cost models use baseline cost 100 and exponentiated log ratios. The heavy-tail model uses Student t with three degrees of freedom. The outlier model adds a symmetric 50-standard-deviation displacement with probability 0.01. The stationary AR(1) coefficient is 0.8. Independent session means combine a shared normal session effect with the average of two independent within-session effects. Cluster-median frames share their entire random session effect, giving within-session correlation one. The bootstrap compares 100 genuine paired sessions against the incorrect treatment of their 200 frames as independent clusters.

[simulation_reference.py](../tests/Fixtures/statistics/simulation_reference.py) computes acceptance envelopes before generating observations. For each prespecified counter it uses SciPy binomial equal-tail quantiles, allocating a total Monte Carlo acceptance error of 0.001 across all criteria by Bonferroni. Normal TOST power is integrated over the independent sample-variance distribution; useful-effect power uses the noncentral t distribution. Regenerating the plan is an explicit review operation, separate from executing it. The execution path rejects a plan that differs from that protocol and does not adapt thresholds to observed outcomes.

Build the Release solution, then run `tests/run-statistical-qualification.ps1`. Python with NumPy/SciPy supplies an independent oracle; `Tedd.DotNetLab.StatisticalQualification` runs the production estimators on the same seeded models. Outputs reside in a unique directory beneath `D:\Workspaces\AI\dotnetlab-implementation\statistical-qualification`. The runner compares all counter totals and first-experiment numerical outputs, enforces the frozen envelopes, and writes durable per-design checkpoints. A failed envelope or oracle mismatch remains a failed qualification and a nonzero exit. Optional `-Design ID` runs a subset whose report explicitly has `complete=false`; it cannot establish full-suite qualification.

The cluster simulation uses 1,000 bootstrap resamples at the median, as frozen in its plan, while the ordinary product default remains 10,000. It preserves within-session dependence and compares the resulting coverage with deliberately incorrect independent-frame resampling. Heavy-tail/outlier stress models are explicitly blocked for unqualified distribution assumptions; unresolved AR(1) dependence provides descriptive output. Their naive calculations remain diagnostic counters and cannot acquire qualified status from favorable coverage. Adaptive exploration is blocked, while the fresh simulated confirmation partition is assessed separately; this simulation does not certify actual normal-build process execution.

Reports retain model parameters, sampling/analysis identity, seeds, experiment/resample counts, acceptance criteria, numerical agreement, failures, runtime/platform, plan/oracle hashes, and production/runner assembly hashes. Passing qualifies only the frozen synthetic model and implementation. A changed estimator, protocol, runtime, or dependency requires independent numerical and simulation review; real-workload independence and representativeness remain separate assumptions.

The retained independent [simulation oracle](../tests/Fixtures/statistics/simulation-oracle.json) and [qualification report](../tests/Fixtures/statistics/simulation-results.json) are bound to the frozen plan and generator hash. The fast reference gate checks completeness, unchanged model/criteria bindings, independent agreement, and every recorded acceptance decision. Executing the ensembles is a separate statistical lane; reading historical successful results alone does not qualify a changed engine.
