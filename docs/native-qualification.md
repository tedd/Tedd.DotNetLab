# Native inspection qualification

This record supports review of the FSS native-inspection gate. Reproduce the Windows checks with `native/build-native.ps1`, a Release solution build, and the `ProfilerTests`, `LiveProfilerTests`, `PlatformSnapshotTests`, and `NativeAnalysisTests` test classes.

Linux x64 has a separate startup adapter. `tests/run-linux-transport.ps1 -Distribution Ubuntu -NativeStartup` builds its shared library with the installed Clang/CMake/OpenSSL toolchain, runs native ABI/CIL/inliner contracts, and executes inspection, caller recompilation, selected probes, controller transactions, and process-death recovery alongside the managed Linux lane. Catalog fixtures use the runner's bounded native ext4 image. The tested toolchain is Clang 18.1.3 and OpenSSL 3.0.13; each run retains exact binary hashes, dependency resolution, runtime, kernel, and distribution metadata. The official CoreCLR 10.0.12 PAL declarations, interface GUID definitions, source URLs, hashes, and license are in `native/dependencies.lock.json` and `native/vendor/coreclr-pal`.

The Linux factory loads through the CoreCLR startup profiler ABI and obtains `ICorProfilerInfo12`. A registered profiler-owned worker answers bounded runtime-discovery, granted inspection, and disposable ReJIT/probe commands over a same-user Unix socket in a private temporary directory. Kernel credentials, PID/start identity, schema, epoch, request bytes, nesting depth, response bytes, and a ten-second I/O deadline are checked. Frames are capped at 1 MiB. The socket is mode `0600`; cancellation wakes the worker, joins it, and removes only its owned socket inode. Handshake discovery refreshes the actual native epoch; snapshot and changing commands require an exact epoch. Attach activation remains unsupported on Linux. A loaded profiler remains part of the recorded observer footprint; native quiet and selected-probe execution use the separate verified admission below.

| Dimension | Verified scope |
| --- | --- |
| Host and runtime | Windows x64 & Linux x64: any CoreCLR `.NET 6.0+` target (including `.NET 8`, `9`, `10`, `.NET 11` RCs/previews, `.NET 12+`); source-audited matrices for `10.0.12`, `10.0.13`, `11.0.0-rc.2.26504.105` |
| Native toolchain | Windows: Visual Studio 2026 Insiders, Clang 22.1.3, SDK 10.0.26100.0; Linux: Clang 18.1.3, CMake 3.28.3, OpenSSL 3.0.13 |
| Activation | Windows startup/attach and Linux startup; `ICorProfilerInfo12` and callback interfaces 1–4 |
| Method identity | Explicit MVID and MethodDef token; concrete module-load identity; module file SHA-256; metadata signature |
| Supported modules | Nongeneric methods in nondynamic, noncollectible modules |
| Acquisition | Profiler-owned thread registered with `InitializeCurrentThread`; runtime-provided version addresses, extents, and mappings |
| Lifetime boundary | No executable address is retained for later dereference; copied bytes remain independently decodable after target exit |

`GetNativeCodeStartAddresses`, `GetCodeInfo4`, and `GetILToNativeMapping3` supply existing code metadata. Each array query has a count bound. The profiler copies only reported extents, caps aggregate code at 256 KiB, and verifies the JIT/module observation epoch before publishing a snapshot. Windows uses `ReadProcessMemory` on its own process; Linux uses `process_vm_readv` on its own process and requires an exact-length copy. An unreadable extent rejects acquisition. A version race yields an error rather than a claimed stable body. Raw mapping sentinels are retained; only mappings within the first reported extent receive qualified region offsets. Tier identity remains `unknown`.

Outside measurement, the controller may reacquire an explicitly rejected `version_changed` snapshot with the same selector, process/start identity, execution epoch, and inspection grant. The policy allows at most three commands with a cancellable 25 ms delay and audits retried rejections as `native_snapshot_rejected`. The controller consumes the inspection grant before each send; native authorization independently counts authorized commands, including version rejections. No retry expands the grant. Rejected bytes are never sealed as consistent evidence. Every successful response still passes the original identity/body/version/map validation. Persistent instability, changed target/epoch, denied permission, cancellation, and other failures terminate acquisition. This policy applies only to snapshot reads; mutation submission and restoration retain their separate reconciliation rules.

The retained module file hash identifies the available build image. It does not establish that every method in an arbitrary process matches its disk image. Inspection reports original/current CIL from this profiler's unreplaced body and requires a selected module hash and signature. Mutated bodies require separate transaction evidence.

Tests verify startup identity, stale PID/start identity, schema rejection, grant scope and epoch rejection, copied native bytes, original/current IL hash equality, offline decoding after process exit, persisted and pinned artifacts across controller restart, and exclusion during registered scenario execution. The portable fixture also generates methods and forces GC while acquiring snapshots; each acquisition must yield a validated copy or explicit `version_changed` rejection. Generic and uncompiled selections cannot trigger implicit invocation. Imported snapshots retain `imported_snapshot_unverified` status; only the acquisition record establishes live identity. A snapshot never proves which body executed in an earlier experiment.

Attach activation, generic instantiations, collectible/dynamic modules, arbitrary application timing intervals, and other runtime versions require separate qualification. Windows/Linux inspection, mutation, controls, and native session-series workflows are confined to the documented fixtures and method subsets; they do not establish complete platform certification. Normal-build confirmation retains its separate qualification below.

The pinned API declarations and license hashes are in `native/dependencies.lock.json`. Legal-call-context review uses exact runtime sources recorded in `native/call-context-matrix.json`, `native/call-context-matrix-net10.13.json`, and `native/call-context-matrix-net11.json`. The shared `ICorProfilerInfo12` ABI is negotiated independently in each target. The implementation's entry-point contracts are version-specific; this qualification does not infer that arbitrary suspension makes other profiler calls legal.

## Profiler call-context matrix

[The versioned matrix](../native/call-context-matrix.json) records every `ICorProfilerInfo12` call in both adapters, its pinned runtime entrypoint and GC contract, its project call context, and its platform scope. COM identity/reference-count operations are excluded. `SetEventMask2` runs during startup initialization. Discovery, metadata, inspection, inliner enumeration, ReJIT submission, and revert calls run on the profiler-owned worker. `InitializeCurrentThread` precedes inspection; the worker never executes managed workload code or suspends the runtime.

CoreCLR's `SYNC` entrypoints permit a profiler-created thread as well as qualifying callbacks. GC-triggering calls in callbacks have additional runtime restrictions; this project performs those calls on its worker. `ASYNC` is an entrypoint allowance, not permission to acquire arbitrary pointers safely. The source's attach flags describe runtime allowances; the product's startup qualification remains narrower.

| API group | Pinned entrypoint / GC contract | Project use |
| --- | --- | --- |
| `InitializeCurrentThread`, `GetRuntimeInformation`, `GetModuleMetaData`, `GetFunctionFromToken`, `GetCodeInfo4` | SYNC / GC_NOTRIGGER | Registered worker |
| `EnumModules`, `GetReJITIDs` | SYNC / GC_TRIGGERS | Registered worker |
| `GetILToNativeMapping3` | SYNC / disabled GC_NOTRIGGER contract | Registered worker; no no-GC guarantee |
| `GetModuleInfo2`, `GetFunctionInfo`, `GetILFunctionBody`, `GetNativeCodeStartAddresses` | ASYNC / GC_NOTRIGGER | Registered worker |
| `SetEventMask2` | ASYNC / GC_NOTRIGGER | Startup initialization |
| `EnumNgenModuleMethodsInliningThisMethod` | SYNC / GC_TRIGGERS | Registered worker; incomplete enumeration rejects preflight |
| `RequestReJITWithInliners`, `RequestRevert` | SYNC / GC_TRIGGERS | Registered worker; frozen callee/caller scope |
| `ICorProfilerFunctionControl.SetILFunctionBody` | Callback-provided control / GC_NOTRIGGER | `GetReJITParameters`; prevalidated body copied, control pointer not retained |

Observation callbacks only update bounded epoch, caller, or mutation state. `GetReJITParameters` publishes approved bytes through its supplied control; shutdown cancels and joins the worker. Metadata enumeration, snapshot acquisition, and mutation submission do not run inside those observation callbacks. GC-triggering enumeration and the disabled mapping contract mean an unsuspended snapshot does not establish absence of GC perturbation.

`python tests/native_call_context_audit.py` checks production API coverage. Select another exact runtime with `--matrix <matrix.json>` and supply `--runtime-source <proftoeeinterfaceimpl.cpp> --rejit-source <rejit.cpp>` to check its source hashes and runtime contracts; URLs and hashes are in each matrix. The audit reads bounded files and never downloads or executes runtime source. Run its parser and rejection tests with `python -B -m unittest discover -s tests -p native_call_context_audit_tests.py`. This static review supplements the real `NativeStartupTests`, `PlatformSnapshotTests`, `LiveProfilerTests`, `RejitTests`, `InlinerTests`, and `MutationRecoveryTests` fixtures; it does not certify unexecuted runtime contexts.

## ReJIT feasibility fixture

Windows and Linux qualification includes the restricted caller/inliner handling and controller transactions below.

`RejitTests` and `InlinerTests` exercise real `GetReJITParameters`, `SetILFunctionBody`, compilation callbacks, and `RequestRevert` in explicitly disposable startup targets. The selected body must be an already compiled, nongeneric, noncollectible, static `Int32` method with at most four `Int32` arguments. Bodies use complete tiny or twelve-byte fat headers, at most 4 KiB, and existing bounded `Int32` local signatures. Native validation checks instruction boundaries, branch destinations, stack merges, local/argument indexes, and every reachable return. Calls can reference the selected MethodDef for recursion; arbitrary call targets and exception sections are rejected.

The request uses `RequestReJITWithInliners` with flags `BLOCK_INLINING | INLINING_CALLBACKS`; this does not globally disable inlining or optimization. Startup `JITInlining` observations retain a conservative potential-caller graph without rejecting inlining. Worker-side discovery expands its transitive closure and checks loaded precompiled-module inliners. `NoInlining` methods have a separately reported exclusion guarantee. Discovery overflow, incomplete native enumeration, unsupported caller instances, or more than 31 callers blocks preflight. Callers must be nongeneric, noncollectible, concrete retained method instances with bodies of at most 4 KiB. These restrictions are reported by the independent ReJIT/inliner/restore/probe capabilities and method preflight.

The live acquisition and immutable candidate retain each caller's MVID, module file hash, module-load identity, MethodDef, signature, and original CIL hash. Mutation subgrants bind both candidate bytes and the complete ordered caller manifest. Native preflight revalidates that manifest. Callbacks can copy the prevalidated candidate or approved unchanged caller bodies; unknown affected functions taint the target. Matching compilation is required for every caller before measurement. Restoration explicitly reverts the callee and all frozen callers and checks each returned status. The scenario declares quiescence/correctness coverage of every affected scope. This follows the [runtime inliner ReJIT API](https://learn.microsoft.com/en-us/dotnet/core/unmanaged-api/profiling/icorprofilerinfo10-requestrejitwithinliners-method) and the [native inliner enumeration contract](https://learn.microsoft.com/en-us/dotnet/framework/unmanaged-api/profiling/icorprofilerinfo6-enumngenmodulemethodsinliningthismethod-method).

Submission increments the execution epoch and blocks measurements. The harness drives a registered synchronous setup batch without a measurement timer, finishes cleanup, and reports application-owned correctness. Matching compilation completion and successful setup are both required to unblock measurements. Original restoration checks aggregate and per-method status, increments the epoch, and requires a separate original-body setup oracle. Original and replacement hashes remain distinct in versioned snapshots.

The fixtures cover a semantics-preserving integer expression and a deliberately incorrect return value. The latter cannot become measurable and is restored before another measured run. `InlinerTests` verifies an optimized original caller without a callee call, exact selected counts after caller recompilation, detection of an incorrect callee that stale inline code would conceal, caller-scope/grant rejection, and per-caller restoration. `MutationRecoveryTests` verifies controller-death recovery of an installed callee probe and caller closure. The native graph contract tests transitive/cyclic closure, method bounds, and observation overflow. The precompiled enumeration path rejects incomplete results; these Windows/Linux fixtures do not qualify arbitrary ReadyToRun applications. Normal-build confirmation follows the independent process workflow below.

Each native session permits at most 32 candidate submissions and 8 MiB of cumulative observed native regions. Verification obtains extents for the compiled selected method and every approved caller on the registered control worker. Accounting distinguishes function, ReJIT version, and region address; repeated observations cannot double-count an unchanged extent. The bounded table holds at most 8,192 region identities. Missing extent evidence, capacity exhaustion, or byte-budget exhaustion requires a fresh process. This counter covers observed compiled regions, including retained historical observations; it does not measure all runtime bookkeeping or assert that old code has been reclaimed.

Windows also limits sampled private-commit growth to 128 MiB above the first authorized native-preflight observation. [Windows `PrivateUsage`](https://learn.microsoft.com/en-us/windows/win32/api/psapi/ns-psapi-process_memory_counters_ex) measures process commit charge, so application allocations and runtime memory contribute to this conservative session limit. Samples occur at native control boundaries; the recorded peak is the maximum sampled value, and transient growth between those boundaries can escape observation. Accounting does not impose an operating-system allocation cap. Missing Windows accounting blocks further mutation. Linux private-commit accounting is `not_collected` and requires independent memory qualification.

Native mutation status and retained verification-journal evidence include `resource_budget`: limits, observed native bytes/region count, private-commit availability/baseline/sampled peak/growth, `restart_required`, and `restart_reason`. Exhaustion remains latched even if memory subsequently falls. Further preflight or application returns `resource_limit`; original restoration and its application-health oracle remain available. A successful restore does not reset the session budget. An application rejected before submission retains a bounded `resource_budget_rejected` journal observation when native state remains available; failed evidence retrieval is explicitly recorded. `MutationSessionBudgetTests` exercises hundreds of real verified applications/restorations across fresh Windows startup/attach identities, the 32-candidate boundary, and a retained-allocation stimulus crossing the private-commit limit. Native budget contracts cover byte limits, deduplication, overflow, missing accounting, and latched restart behavior.

`ActiveFrameRejitTests` qualifies Windows startup and attach behavior with a compiled, nongeneric, no-inline `Int32` loop. A test-owned process exposes fixed bounded fixture commands; it is protected by a kill-on-close job. The observer validates PID/start and thread ownership, then obtains the old thread's instruction pointer within retained original native regions before application and after a future call returns the replacement value. The old call must subsequently return its original arithmetic checksum. Revert must restore subsequent-call behavior. Compilation without the application-owned setup oracle remains pending and cannot certify measurability or promotion.

The registered-execution fixture separately requires rejection of preflight/application while its old frame is executing, with unchanged mutation count and epoch. Only after the execution joins and acknowledges quiescence can original-body ReJIT, untimed setup verification, and restoration proceed. Both fixtures explicitly retain their per-method `NoInlining|AggressiveOptimization` flags. The test-only observer uses [Windows thread-context retrieval](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-getthreadcontext), which requires temporary thread suspension. It resumes the thread in `finally` and issues no CLR API while the thread is suspended. This external observation is intrusive, is not exposed through MCP, and supplies no performance-calibration evidence or generic stack-collection capability.

## Windows attach qualification

The Windows adapter accepts an explicit `DiagnosticsClient.AttachProfiler` activation with bounded UTF-8 JSON client data: `schema_version`, `target_id`, `process_id`, `start_time_utc_ticks`, and absolute `workspace`. The PID/start-derived identity must match the process. If the target declares `DOTNETLAB_WORKSPACE`, the supplied workspace must match it exactly. Data is capped at 16 KiB, nesting at 16 levels, and workspace text at 4 KiB. Unknown fields, malformed data, incompatible schema, relative paths, and mismatched identity/workspace reject initialization. The adapter starts its authenticated endpoint after `ProfilerAttachComplete`; the handshake records completed activation and the actual low event mask `0x40024`. The pinned header contract verifies that every enabled flag is attach-allowable.

Attach inspection preserves existing-code acquisition and reports pre-attach caller history as `not_collected_pre_attach_history` for inlineable methods. Mutation requires the target's own `DOTNETLAB_DISPOSABLE=1` opt-in, explicit content/method/execution grants, and verified no-inline static `Int32` methods. Both controller and native preflight enforce that boundary; empty post-attach observations cannot establish an empty earlier caller closure. Selected probes and attach caller recompilation require separate qualification. Incorrect candidates remain unmeasurable and require verified original restoration. Runtime inspection and invocation rules remain the same as startup, and a loaded attached profiler remains part of the observer footprint even when the startup profiling environment setting is `0`.

`lab.experiment` action `prepare_profiler_attachment` freezes a discovered target at epoch zero, the configured native DLL's absolute path, SHA-256 and length, the pinned runtime image hash, profiler ID, flags, and a 30-second activation budget. The packaged host uses its adjacent `Tedd.DotNetLab.Profiler.dll`; MCP requests cannot select a library path. The file must be a native AMD64 DLL no larger than 16 MiB and cannot traverse reparse points. Binary and runtime identities are rechecked before loading, with the approved DLL held against replacement during activation.

While the workspace controller is stopped, the human CLI issues `grant-profiler-attach <workspace> <plan-id> <seconds> 1`. This distinct permission binds the exact plan and PID/start session and permits one activation. `lab.run` action `attach_profiler` takes `plan_id`, `grant_id`, and `idempotency_key`. Loading runs in a bounded child host with a cleared environment, a 256 MiB Windows Job Object, and no catalog access. Success requires the approved loaded path and the completed identity/flags/workspace handshake. An immutable outcome and pinned artifact retain the result. Discovery, ordinary observation, and a missing profiler endpoint do not authorize loading.

Cancellation, timeout, lost acknowledgement, or controller interruption after durable activation intent leaves the target isolated. `lab.run` action `reconcile_profiler_attachment` takes the source `operation_id` and an unexpired matching `grant_id`; it verifies completed activation or disappearance of the original process without loading again or consuming another activation. Reconciliation clears only that source's taint. Replay cannot clear a subsequent operation's taint. An unresolved live target requires disposal. Loading does not establish a pristine observer state, and this protocol does not isolate hostile code operating under the same user identity.

`NativeAttachTests` compares startup and attach transactions, observes compilation/correctness, verifies restoration and restart retention, and tests malformed activation, caller-history, and nondisposable boundaries. `ProfilerAttachmentTests` covers CLI/MCP activation, independent permission and binary scope, worker deadlines/cancellation, uncertain acknowledgements, and source-bound reconciliation. `DualRuntimeTests` exercises startup/attach inspection, ReJIT and verified restoration across different Windows controller and target versions, including a `net11.0` workload. The exact Windows runtime matrix and documented disposable fixtures define the qualified scope. Linux attach remains unsupported.

## Linux controller and selected-probe admission

The disposable Linux startup fixture accepts `preflight`, `apply`, `mutation_status`, `verify_mutation`, `restore`, and `reconcile_mutation` for the same restricted methods and frozen caller closure as Windows. Replacement and selected-probe bodies use the shared bounded CIL validator. Each changing request requires an exact process/start/epoch identity and a `replace_il` or `install_probes` grant binding workspace, method scope, replacement/caller hash, expiry, and operation budget. Unknown mutation fields are rejected. Nondisposable targets report mutation/probes/restoration unsupported and reject mutation before admission.

Submission increments the execution epoch and blocks registered measurement. Real ReJIT callbacks retain version identity and compilation status; the application-owned untimed setup oracle must pass before `verify_mutation` unblocks execution. Incorrect replacements remain unverified. Original restoration checks the aggregate and per-method `RequestRevert` status, increments the epoch, and requires another original-body setup oracle. Native snapshots label copied ReJIT versions with their approved CIL bytes and hashes while preserving original-body identity. A tainted state denies further execution; uncertain mutation is not automatically replayed.

`MutationServiceTests`, `InlinerTests`, and `MutationRecoveryTests` qualify Linux journal-before-submission ordering, exact caller/grant scope, incorrect-candidate restoration, per-caller compilation/restoration, and controller-death reconciliation. `LiveProbeTests`, `ProbeServiceTests`, and `FaultProbeBoundaryTests` cover normal/exceptional completion, recursion, bounded helper counts/timing, public execution, evidence retention, and restoration. The managed controller exposes the independently negotiated native capabilities for this startup subset.

Linux native execution requires the retained Linux/x64 footprint, profiling enabled, no startup hooks/additional dependencies, and an identity/epoch-matched pinned startup profiler with verified probe/caller capabilities. The controller obtains that handshake over authenticated IPC and checks workspace qualification. `targeted-probes` additionally requires an installed active helper plan with method scope; quiet native batch/individual execution and diagnostic EventPipe execution require inactive probes. Diagnostic profiles also require enabled diagnostics and separate observation permission. Caller-supplied profile or footprint labels cannot supply these proofs. Compilation health, grant, workload scope, and quiescence checks remain mandatory. Candidate/original-body ReJIT performance requires a frozen completed compilation control matching target session, method/callers, runtime, flags, workload, and warm-up policy. `CompilationControlTests`, `CompilationAdmissionTests`, `NativeTrialTests`, and `NativeSeriesTests` exercise these workflows independently on Linux. `NativeDiagnosticExecutionTests` covers the four diagnostic profiles with original compiled code and controlled candidate ReJIT, capture/marker/regime bindings, missing-control rejection, restoration, and retained analysis after target exit. A quiet compilation control establishes its protocol and code-regime prerequisites; it does not calibrate an EventPipe profile's perturbation or establish performance equivalence across observer regimes. Promotion requires independent normal-build confirmation.

## Independent normal-build confirmation

`lab.experiment` accepts `register_normal_build` with a managed entry assembly name and a manifest of sealed artifact IDs. Qualified bundles contain at most 64 files and 128 MiB: managed IL DLLs with a complete flat dependency closure, the entry's dependency manifest, and its runtime configuration targeting a supported CoreCLR `6.0+` runtime (preserving any configured `rollForward` policy, defaulting to `Minor`, and pinning the resolved concrete `--fx-version` across all sessions of a confirmation run). The manifest's runtime participates in build identity and selects the owned child runtime independently of the controller. Native, RID-specific, satellite, and external dependency assets are excluded. Both arms use identical harness/dependency code and runtime settings; only the entry assembly is the declared code treatment.

`create_confirmation_plan` freezes the selected candidate, source patch or source manifest, an explicit source-equivalence rationale, the exact revisions/hashes of prior exploratory evidence, both builds/variants, and a two-arm quiet analysis/sample budget. Later exploratory narrative revisions do not replace those references. The source-equivalence rationale is a review assertion; the engine does not establish equivalence for arbitrary inputs. Plans require independent blocks, at least the declared minimum block count, warm-up, and an elapsed-cost primary metric. Each declared guardrail requires a matching metric policy with explicit unit, observation type, direction, effect scale, margins, and descriptive/inferential role. Unknown metrics and inconsistent families reject the plan. A Boolean `fresh_normal_build` on an ordinary same-process plan cannot establish confirmation.

The human CLI issues `grant-confirmation <workspace> <plan-id> <seconds> <maximum-operations>`. Issue it while no workspace controller is running, then restart the MCP controller; the catalog permits one controller at a time. This permission authorizes startup of those exact registered application bundles, including their application startup effects; registration alone authorizes no launch. `lab.run` uses `start_confirmation` with the plan, grant, and idempotency key. Each frozen plan has one durable execution: retries return it, and a changed request cannot add samples. A separate frozen plan is required for another experiment; its rationale and exploratory provenance remain explicit.

Each randomized matched block starts two distinct owned processes. The controller launches the retained `dotnet` host with a verified staged entry assembly and fixed `--harness <workspace>` arguments. Its environment uses a small operating-system allowlist, task-owned temporary paths, diagnostics/profiling disabled, and no inherited startup hooks or additional dependencies. `HarnessHost.RunOwnedAsync` provides readiness, one measurement execution, and orderly exit on stdin shutdown or controller pipe EOF. Kernel process/start identity, runtime, complete DLL hashes, inactive probes, debugger/profiler absence, input/version, completed operations, correctness, and quiescence are verified. The process is joined before a completed session is retained; cancellation/failure kills and joins it, while uncertain termination taints the operation. Staging directories are removed after join. Copy, cancellation, or staged-hash failure before launch removes the owned partial directory and preserves sealed source artifacts. Scratch workspaces must reside in a fully qualified, non-root, reparse-point-free workspace directory.

`lab.compare` with `normal_build_confirmation=true` checks the sealed completion manifest and retained measurement/source artifacts, the complete original budget, distinct process sessions, pre-registration, matching runtime fingerprints, and every correctness gate. It pins the decision evidence and evaluates the preregistered primary/guardrail vector. Promotion eligibility requires a useful primary benefit and every mandatory guardrail; equivalent, inconclusive, invalid, interrupted, or live-ReJIT-only primary results remain ineligible. Unknown mandatory guardrails block promotion; predeclared descriptive guardrails remain visible without gating it. The decision and primary comparison link a bounded `objective_vector` index whose artifact retains full input provenance. Eligibility is evidence for source review and performs no source edit, commit, deployment, or publication. Disabled CLR diagnostics establishes the controlled runtime observer state; this workflow does not exclude unrelated operating-system observers.

For ordinary completed scenario executions, `lab.compare` with `include_objectives=true` returns bounded vector indexes. Supported measurement objectives include elapsed cost, throughput, and process/eligible-thread allocation deltas. Allocation uses absolute differences, including zeros. Target-clock-aligned GC overlap requires frozen diagnostic-window policy and retained valid capture evidence; quiet envelopes report it as `not_collected`. The fixed family covers every inferential arm/metric comparison. Pareto dominance remains unresolved when intervals overlap or any objective lacks inference. The [statistical contract](statistical-contract.md) defines the formulas, assumptions, directions, guardrail rules, numerical limits, and interpretation.

`ConfirmationTests` exercises two CPU-only normal builds with an integer-sum oracle, 20 fresh process sessions, concurrent/idempotent comparison, restart retention, hook-environment exclusion, staging cleanup, grant-scope rejection, correctness failure, cancellation/join, corrupt build rejection, a one-measurement owned-process budget, and EOF shutdown. Its `net11.0` fixture verifies exact-runtime launch and complete session identity across controller versions. `HarnessTests` retains rejection of a fresh-process claim by an ordinary runner. These checks qualify the documented runtime matrix and entry-assembly treatment, not arbitrary applications or source equivalence outside their declared oracle.

Linux confirmation uses the exact pinned `dotnet` host and kernel boot/start counters for process identity. Its child environment retains the private task IPC directory, constrained to the Unix socket path budget, while excluding inherited hooks, profiling, and additional dependencies. Runtime OS family and the complete managed-file inventory are checked before and after measurement. Invalid IPC configuration rejects before staging. Cancellation and failure join the owned process before removing its launch directory. Staging/catalog files remain on the supported native local filesystem; Unix IPC uses the task's private temporary filesystem.

## Controller transaction evidence

The MCP host registers `lab.patch` only with `serve <workspace> --enable-native-extension`. Default serving exposes six base tools and rejects unregistered patch calls. Extension registration adds no executor or permission issuer and does not load a profiler. Human CLI grants and all application/native boundary checks remain independent prerequisites. Unknown server switches reject before workspace creation.

`MutationServiceTests` verifies the public controller path for the integer-expression fixture. Candidate registration requires a sealed replacement-input artifact and a verified live acquisition record. The immutable manifest identifies the module load, method, signature, base/current body, original body, transformation, resolved CIL policy, and components. A human-issued parent grant binds the complete manifest and method scope; native subrequests inherit its target, expiry, and content scope.

The controller commits an immutable root and hash-chained `mutation_event` records to the local catalog before native submission. Preflight validates the live base and module-load identity again. Compilation-driving setup uses the registered oracle's declared method scope, remains untimed, and completes cleanup before reporting correctness. Candidate failure triggers an original-version restore and a separate original-body oracle. Unknown restoration produces a tainted outcome and denies further leased work. Interrupted mutation leases are tainted during catalog recovery.

`lab.patch` exposes discriminated `preflight`, `apply`, `restore_original`, and `recover_interrupted` actions. Applying, restoring, and recovering return durable operation IDs. Retained outcomes distinguish measurable, restored, and tainted states. The final mutation journal checkpoint precedes terminal publication. Terminal status, owned-lease release, and any taint commit in the same catalog transaction; delayed cleanup cannot release or taint a successor's lease. Idempotent retries return the original operation after an epoch change. Mutation outcomes always retain `promotion_eligible=false` until independent normal-build confirmation exists. Original-body ReJIT inputs can be registered through the same candidate pipeline for A/A control; restoration remains a distinct operation.

Interrupted mutation leases retain their source operation as a recovery authority. Ordinary capture, execution, and mutation remain blocked. Explicit recovery requires current candidate-scoped mutation/probe permission and scenario-execution permission; expiry is enforced and recovery does not extend a grant. The controller validates the original immutable journal and hash chain before contacting the native boundary. Native reconciliation binds the selected module load, method scope, original body, active transaction, current body, and epoch. A known candidate receives an original-version revert and an untimed reset/correctness oracle. An empty native mutation session with the unchanged original body receives a `not_applied` result and an application-health oracle.

Recovery clears only a recorded controller-interruption taint, after sealed and pinned native/health evidence and the verified completion are committed together in the catalog. Interrupted execution, native taint, foreign transactions, uncertain restoration, and incomplete health/evidence cannot use that path. A controller exit during recovery preserves the original interruption authority and permits another explicit reconciliation. Missing preparation or unknown native state requires a fresh target. Recovery never claims pristine-runtime status or promotion eligibility.

`MutationRecoveryTests` uses a separate controller fixture that immediately exits without rollback at preparation, submission intent, compilation driving, candidate verification, outcome commit, probe setup, and original restoration boundaries. It verifies restart reconciliation, ordinary-work exclusion, exact source/epoch bindings, pinned evidence, later correct execution, expired-grant rejection, invalid-journal rejection before live calls, and foreign-native-transaction taint. These checks certify the disposable Windows/Linux fixture and cooperative oracle; they do not certify recovery of external side effects or arbitrary application state.

`restore_original` selects the CLR's original method version, including every approved caller; it does not select the preceding experimental candidate. To select an earlier candidate, use `apply` with that candidate's retained ID, matching grant, current epoch, and a new idempotency key. Its frozen base body must match the live body. Reapplication receives a new transaction, observed compilation, setup oracle, and resulting epoch; replay of the same request retains that operation. Restoring original code neither resets runtime history nor establishes promotion eligibility.

`CandidateReapplicationTests` covers the sequence A → B → original → A through the public MCP adapter on Windows startup/attach leaves and a startup callee with an approved inliner. The named estimand is the geometric mean of session-mean matched log batch-cost ratios. ## Local transport frame limits

The client verifies the kernel-reported server PID before transmitting a grant. Native pipe IO uses overlapped operations, a stop event, and a ten-second total frame deadline. The client acknowledges a fully read reply before server disconnect; shutdown does not wait indefinitely for a partial control frame. Request and response frames are bounded to 1 MiB, and native JSON nesting is limited to 32. Oversized replies return a typed resource error. Client timeout and disconnect errors preserve unknown submission semantics for controller reconciliation.

`NativeTransportFaultTests` checks shutdown with a partial header and rejection of deeply nested input followed by a successful handshake. These tests cover IO cancellation and parser bounds; they do not establish that arbitrary CLR API work can be interrupted during runtime shutdown.

## Selected synchronous probes

`LiveProbeTests`, `ProbeServiceTests`, and `InlinerTests` qualify count and inclusive elapsed probes on integer-expression, recursive, loop, division, and caller/callee fixtures in the restricted `Int32` subset. The application explicitly loads `Tedd.DotNetLab.Probes` through `HarnessProbeSupport`; the harness package has no dependency on that optional package. Target modules must already contain the approved `ProbeRuntime.Enter(Int32)` and `Exit(Int32)` member references. Fault tracking also requires `ExitExceptional(Int32)` and an existing all-`Int32` local signature with a spare return slot. Native preflight verifies their type, assembly, signature, loaded helper file hash, and noncollectible lifetime.

The normal-completion rewriter preserves the selected base instructions, local signature, and return values. It instruments every supported return and widens branches with recalculated destinations. `prepare_probe.track_exceptions=true` uses a separate certified fault template: entry outside the protected region; each original return stores its value and uses `leave` to a normal-exit epilogue; a single fault clause calls the exceptional-exit helper and terminates with `endfinally`. Existing original locals keep their types and indexes; the selected expanded signature supplies a separate return local. Native validation independently compares the entire emitted body, branches, aligned exception table, and metadata bindings with the certified rewrite before `SetILFunctionBody`. Probe installation requires `install_probes` permission; arbitrary CIL replacement permission does not authorize exception sections or helper calls. Plans retain helper identity, timing mode, base/current/original body hashes, resolved metadata policy, nesting/thread limits, and exception scope.

Setup drives compilation and validates application behavior outside measurement. Its probe totals are checked against each scenario's declared invocations per completed operation and retained separately before a new measurement session begins. A scenario without that declaration requires positive, complete setup evidence and records the expected count as unknown. The fixtures verify exact entered/normal/exceptional counts, zero in-flight frames, prewarmed thread slots, distinct count/timing payloads, sealed evidence artifacts, and original-version restoration with the helper inactive. The recursive fixture records six invocations per operation; the loop fixture exercises existing locals and backward branches. The division fixture catches the original `DivideByZeroException` outside the selected method and verifies separate normal and exceptional outcomes. `lab.patch` provides `prepare_probe` and `flush_probes` alongside apply/restore actions.

`targeted-probes` plans require an active verified probe plan and a scenario that declares the selected method scope. Each run retains the helper/plan observer fingerprint. `quiet-validation` rejects active selected probes. Flushed totals cover the explicitly delimited probe session, including any warm-up calls in that session; they are not retroactively assigned to arbitrary earlier runs. The elapsed value is inclusive wall-clock ticks, not exclusive CPU time.

Fault-mode exceptional completion means managed fault unwinding, not the instant an exception is thrown. The interval ends when the fault helper runs; first-pass exception searches and outer filters can delay that boundary. This follows the control-flow rules in [ECMA-335, Partition I exception handling and Partition III `leave`/`endfinally`](https://ecma-international.org/wp-content/uploads/ECMA-335_6th_edition_june_2012.pdf). Normal-completion mode rejects throwing arithmetic. Fault mode certifies arithmetic exceptions and preserves propagation in the tested subset; original catch/finally/fault/filter regions, arbitrary callees, unverified caller closure, and async/state-machine timing remain excluded. Termination without managed unwind, including process death or stack exhaustion, cannot establish complete coverage.

`CilTests` executes the emitted fault table under the CLR and rejects malformed ranges, cross-region branches, unsupported helper references, and forged return slots. `FaultProbeBoundaryTests` submits altered layouts and metadata bindings directly to native preflight and verifies that neither the mutation count nor epoch changes. Separate helper tests exercise overflow, concurrency, and allocation behavior. Probe overhead and code-generation effects require separate calibration evidence.
