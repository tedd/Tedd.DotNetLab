One repeated scan.
66.4% less time.

Time per matching call on dense inputs with a 16,384-character prefix in Tedd.WildcardMatch.

The matcher repeatedly checked an already-scanned prefix for newlines. Tracking how far it had checked let each retry scan only the new interval.

DotNetLab compared the source change with the original in fresh processes. The smaller dense-input scenario improved by 27.4%; ordinary inputs stayed within the declared ±5% equivalence margin.

Each scenario used ten randomized paired blocks, with a separate baseline and candidate process per block, two warm-up batches, and no excluded or replacement runs. Timings are geometric means of batch means. Four comparisons shared a 5% error budget; the dense-16384 candidate/baseline ratio was 0.3355, with a 98.75% interval of 0.2871–0.3922.

The study covered one pattern and four synthetic input distributions. Host load, CPU affinity, frequency, and thermal state were uncontrolled. The results describe these matching calls; application throughput depends on its workload.

THE SCIENTIFIC METHOD

Observe. Hypothesize.
Experiment. Verify.

Your agent follows an experimental loop: measure a real bottleneck, explain its cause, test a focused change, and check whether the improvement survives independent confirmation.

01 / OBSERVE

Find what costs time.

Profile your workload to locate CPU hotspots, allocations, and GC pauses. Your agent forms a testable hypothesis about the expensive work and the change that could reduce it.

02 / EXPERIMENT

Implement and test a change.

Your agent edits the code, checks its outputs, and compares it with the baseline. Metrics and acceptance criteria are fixed before timing; randomized trials help separate gains from noise.

03 / VERIFY

Keep the supported gains.

Retest baseline and candidate builds in fresh, profiler-free processes. Retain changes that pass performance and correctness checks, revert unsupported candidates, then profile again.

Your application.
Your first investigation.

The installer configures the CLI, MCP server, and companion skill for Codex, Claude Code, Cursor, and Google Antigravity. It downloads a matching release, or builds from source when no release matches.

Run DotNetLab with a .NET 10+ runtime or SDK on Windows x64 or Linux x64. It can investigate .NET 6+ CoreCLR applications.
