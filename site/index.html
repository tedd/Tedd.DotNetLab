THE INVESTIGATION LOOP

Make performance
a testable question.

Carry one hypothesis from diagnostic evidence through a controlled comparison to a fresh-build decision. Preserve the inputs, plans, and artifacts along the way.

01 /

Find the mechanism.

Discover a running process. Capture CPU samples, allocation stacks, GC pauses, and runtime counters. Identify the methods and windows that explain the cost.

Explore the MCP tools ↗
02 /

Control the experiment.

Declare the primary metric, allocation guardrails, warmup, and correctness checks before running a seeded, randomized block comparison.

Read the statistical contract ↗
03 /

Verify the outcome.

Build the candidate and baseline, then compare them in fresh OS processes with diagnostics disabled. Record the adoption decision against retained evidence.

Follow the evidence ↗

A/B, multi-variant, and 2 × 2 factorial designs with paired confidence intervals, multiplicity correction, and equivalence testing.

TAIL LATENCY

Look beyond the average.

Capture per-operation latencies and compare tail quantiles using cluster bootstrap inference across independent blocks.

NATIVE INSPECTION

Inspect what the JIT emitted.

Read live x64 assembly and instruction diffs. Prototype bounded CIL replacements with the optional native CoreCLR profiler and ReJIT tools.

DURABLE EVIDENCE

Keep the reasoning reproducible.

A local SQLite catalog links hypotheses, immutable plans, baselines, and decisions to content-addressed SHA-256 artifacts.

↗

FRESH-PROCESS CONFIRMATION

Measure the normal build.

Confirm source candidates in new, diagnostics-disabled processes, separately from exploratory profiling and live instrumentation.

Native workflows require the optional profiler. Live profiler attachment is supported on Windows x64; Linux x64 supports startup instrumentation. Platform details ↗

Your agent.
A real laboratory.

The companion skill guides tool selection, scoped authorization, measurement, and interpretation. Start with the investigation you need.

  • Bound attachment and execution with scoped CLI grants.
  • Validate semantic output outside the measured interval.
  • Retain evidence across sessions and agent restarts.

GET STARTED

A performance lab.
In your agent's toolkit.

Install the CLI, MCP server, and companion skill for your coding clients. The installer downloads a matching release, or builds from source when no release matches.

Use a .NET 10+ runtime or SDK on Windows x64 or Linux x64. After installation, restart your coding client and run dotnetlab compatibility.
