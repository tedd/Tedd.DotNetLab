# DotNetLab client evaluation — 2026-10-28

Evaluation started 2026-10-28 and concluded 2026-10-29 (Europe/Oslo).

DotNetLab completed controlled optimization, profiling, code inspection and fresh-process confirmation workflows against isolated .NET fixtures. The Codex-generated sum-of-squares change reduced elapsed time by **89.1%** under the frozen confirmation protocol. Client integration and request construction require substantial improvement: nine successful workload sessions included **94 rejected or failed DotNetLab requests out of 384 calls**.

The [evaluation bed](README.md) and [machine-readable evidence](results/2026-10-28/evidence.json) support reproduction and review. The evidence preserves failed requests and unsuccessful setup trials as well as successful measurements.

Lower ratios indicate less elapsed time. These are descriptive estimates from twelve same-process blocks; every formal comparison remained inconclusive because the blocks were not independent. The null control produced no claimed improvement. The large asynchronous difference reflects eliminating deliberately unnecessary suspension in an already-materialized cache, under a contract permitting synchronous completion.

Core completion was more reliable than methodological completion. Only two of nine sessions froze allocation guardrails, and only one recorded a successful terminal hypothesis disposition. Several clients recovered from invalid policy examples by removing guardrails. The core score intentionally does not equate those outcomes with complete adherence to the skill's scientific protocol.

The failed-call count primarily describes argument construction and API discovery, rather than failed measurements. Strict schema validation correctly rejected many requests that models described as endpoint failures; the diagnostic messages often did not explain the rejection sufficiently.

The nine sessions consumed a reported 18,153,524 cumulative input tokens, including 17,507,072 cached tokens, and 57,220 output tokens. These counts include repeated context across requests and are not a price estimate. One session per scenario, without a repeated no-skill control, does not establish the skill's causal benefit or a general model reliability rate.

## Generated source and independent confirmation

Codex replaced the allocating LINQ pipeline in `Candidate.SumSquares` with a loop that widens each integer before multiplication and accumulates under unchecked Int64 arithmetic. The independent oracle covers empty inputs, signed extremes, overflow and reuse of mutated input arrays, in addition to the other client contracts.

The source-edit session completed a pre-change comparison but could not build and measure the changed implementation through its restricted-token compiler path. The evaluator correctly failed its compiled-source binding gate. A trusted launcher then built the inspected snapshot, ran the oracle, and supplied narrowly scoped grants. Codex measured that snapshot in a separate session; it did not claim fresh-process confirmation itself.

The subsequent owner-assisted holdout froze ten paired blocks and launched twenty independent, profiler-free processes. The engine classified elapsed time as `improved`, with candidate/baseline ratio **0.108928**, a **97.5% interval of [0.106607, 0.111299]**, and `promotion_eligible=true`. Allocation remained a descriptive objective. This result concerns the bounded fixture and its frozen warmup/workload protocol; it is not a performance claim about arbitrary applications or DotNetLab's own implementation.

The [source snapshot](results/2026-10-28/codex-sum-squares.cs.txt) and [registered source patch](results/2026-10-28/source-confirmation.patch) preserve the candidate for review. Raw timing/allocation observations, process identities, frozen plans, hashes and confirmation decisions are included in the JSON evidence. Authentication, raw EventPipe traces and unrelated process inventories are excluded.

## Improvement priorities

| Priority | Change | Evidence and intended effect |
| --- | --- | --- |
| P1 | Repair and execute-test the operational examples | Four audited examples failed: the plan omits required guardrail policies and uses `gc.allocated_bytes_per_operation` instead of a registered metric such as `scenario.process_allocation_bytes_per_operation`; candidate `components` uses method names where candidate record IDs are required; confirmation comparison enables mutually exclusive modes; patch import uses `text/plain` instead of an accepted patch/source media type such as `text/x-diff`. |
| P1 | Return field-level validation errors consistently | Rich hypothesis fields, guessed policy shapes and incomplete revisions repeatedly produced generic SDK invocation errors. Preserve strict rejection of unknown fields, but return the action, rejected field, required fields and a valid bounded example. |
| P1 | Support a trusted owner grant workflow for sandboxed clients | Restricted shells failed to access the controller's current-user named pipe. Pre-issued grants worked. Document or broker that path without weakening pipe ACLs or exposing unrestricted grant creation over MCP. Map CLI access failures to structured errors instead of unhandled stacks. |
| P1 | Provide a safe unattended client configuration | Legacy sandbox flags resolved to read-only in one configuration; an unconfigured Windows launcher blocked commands; overlapping roots broke editing; noninteractive MCP mutations required explicit approval configuration. Ship version-tested, task-scoped examples and a preflight. The successful setup retained filesystem isolation and target grants. |
| P2 | Expose metric-policy presets and action schemas through MCP | Only 2/9 sessions retained allocation guardrails. Read-only schema/help resources and validated absolute-allocation presets would avoid guessing units, observation kinds, effect scales and thresholds. A filesystem-free trial could not retrieve the operational reference. |
| P2 | Make hypothesis revisions easier to complete | Only 1/9 sessions reached a recorded terminal disposition. State changes currently require full mechanism/prediction data and the expected revision. Return revision metadata on creation and show complete update payloads, or offer an explicit state-transition operation. |
| P2 | Add exact PID discovery and concise target compatibility | A discovery-only session required four pages to find a supplied PID. Target resolution should avoid dumping unrelated processes. Make compatibility freshness explicit and offer a target-only response. |
| P2 | Investigate controller cold-start failure deterministically | One required-server launch failed before model execution, with `controller_unavailable` and named-pipe wait errors in retained logs. A warm owner connection stabilized the final matrix. The idle window is a hypothesis to test, not an established cause. |
| P2 | Separate read-only polling from destructive operations | `lab.run` marks every action destructive, including status polling, while also dispatching administrative operations. More granular tool boundaries would reduce approval friction without broadening execution authority. |
| P2 | Repair baseline test infrastructure and expand execution evidence | Resolve or explicitly install the intended runtime for confirmation fixtures; repair metadata and missing evidence inputs; use explicit skips for absent fixtures; make short-expiry tests deterministic. CI should run the real-MCP suite on suitable infrastructure in addition to deterministic evaluator tests. |

The [core workflow reference](../../skills/dotnetlab/references/mcp-loop.md) and [advanced reference](../../skills/dotnetlab/references/advanced-lab.md) contain the audited examples. The CLI configuration follows the documented [permission profiles](https://learn.chatgpt.com/docs/permissions) and [MCP approval settings](https://learn.chatgpt.com/docs/extend/mcp); the tested CLI's supported features remain authoritative when documentation describes newer features.

## Scope

The live AI client was Codex CLI. Existing installer tests cover configuration behavior for other supported clients; Claude Code, Cursor and Antigravity agents were not run. Native mutation behavior is covered by the existing repository suite, rather than an autonomous model patching trial. All catalogs and workload processes were task-owned and local. The evaluation changed test infrastructure and evidence, not production systems.
